# docs/

Living notes for the hackathon. Keep entries short; date them (YYYY-MM-DD).

| File | What goes in it |
|---|---|
| [backlog.md](backlog.md) | Ideas we **want to implement**, roughly prioritized. Tick them off when done. |
| [rejected.md](rejected.md) | Ideas we **tried or considered and dropped**, with the reason — so nobody re-proposes them mid-event. |
| [decisions.md](decisions.md) | Ideas that are **good but non-obvious / fragile**. Each entry explains *why* it is the way it is and *what breaks* if changed. Read before refactoring. |

Rule of thumb: if you catch yourself explaining something twice, it belongs in `decisions.md`.

Use the `/log-idea` skill (in `.claude/skills/log-idea/`) to append entries in the right format.
